## 📝 Описание

CustomPotions - это плагин, разработанный специально для сервера CME World, который расширяет возможности системы зелий в Minecraft. Он позволяет администраторам и операторам создавать уникальные зелья с настраиваемыми эффектами, цветами, названиями и рецептами варки через интуитивно понятный графический интерфейс (GUI).

### Основные возможности:

- ✨ Создание кастомных зелий с любыми эффектами.
- 🎨 Настройка цвета зелья (RGB).
- 📜 Определение собственных рецептов варки.
- 🧪 Поддержка всех типов зелий (обычные, взрывные, туманные).
- 💾 Сохранение данных в JSON формате.
- 🔄 Быстрая перезагрузка без перезапуска сервера.

## ⚡ Возможности

### Создание и редактирование зелий

- **Визуальный редактор**: Полноценный GUI для создания и редактирования зелий.
- **Типы зелий**: Поддержка обычных зелий (POTION), взрывных (SPLASH_POTION) и туманных (LINGERING_POTION).
- **Кастомные эффекты**: Добавление любых эффектов зелий с настраиваемой длительностью и уровнем.
- **Цвета**: RGB-настройка цвета зелья для визуального отличия.
- **Названия**: Пользовательские названия с поддержкой цветовых кодов Minecraft.

### Система рецептов

- **Цепочки рецептов**: Создание сложных цепочек варки (например: базовое → улучшенное → расширенное).
- **Базовые зелья**: Использование ванильных зелий (AWKWARD, MUNDANE и т.д.) или других кастомных зелий как основы.
- **Ингредиенты**: Любые материалы Minecraft как ингредиенты для рецептов.
- **Валидация**: Автоматическая проверка корректности рецептов при загрузке.

### Интеграция с игрой

- **Варка зелий**: Полная интеграция с игровой механикой варки в стойке для варки.
- **Выдача зелий**: Команда для выдачи зелий игрокам.
- **Отладочный режим**: Встроенные инструменты для диагностики и отладки.

## 📦 Установка

### Для пользователей

1. Скачайте последнюю версию плагина из раздела [Releases](https://github.com/Kr1sper59/CustomPotions/releases).
2. Поместите файл `custompotions-X.X.X.jar` в папку `plugins` вашего сервера.
3. Запустите сервер (плагин создаст необходимые файлы конфигурации).
4. Настройте `config.yml` под свои нужды (опционально).
5. Добавьте зелья в файл `potions.json` или используйте команду `/cp modify` для создания через GUI.

```bash
# Клонируйте репозиторий
git clone https://github.com/Kr1sper59/CustomPotions
cd CustomPotions

# Соберите проект
mvn clean package

# Файл .jar будет находиться в target/custompotions-X.X.X.jar

  # Время варки зелья в тиках (20 тиков = 1 секунда)

  # Уровень топлива при добавлении пороха дракона
  fuel-level: 20
  
  # Потребление топлива за тик

gui:

  # Размер прыжка по страницам
  page-jump-size: 5
```

### potions.json

Файл с данными о всех кастомных зельях. Формат - JSON массив объектов `Potion`.

#### Структура объекта зелья

```json
{
  "potionId": "haste-potion-1",
  "colour": {
    "r": 255,
    "g": 200,
    "b": 0
  },
  "name": "§eЗелье спешки",
  "type": "POTION",
  "recipes": [
    {
      "ingredient": "BLAZE_ROD",
      "base": "POTION-AWKWARD-STANDARD",
      "result": "haste-potion-1"
    }
  ],
  "effects": [
    {
      "type": "FAST_DIGGING",
      "duration": 3600,
      "amplifier": 0
    }
  ]
}
```

#### Поля объекта

- **potionId** (string): Уникальный идентификатор зелья (не должен конфликтовать с ванильными ID)
- **colour** (object): RGB цвет зелья `{r, g, b}` (0-255)
- **name** (string): Отображаемое название зелья (поддерживает цветовые коды)
- **type** (string): Тип зелья - `POTION`, `SPLASH_POTION` или `LINGERING_POTION`
- **recipes** (array): Массив рецептов варки
  - **ingredient** (string): Материал-ингредиент (например, `BLAZE_ROD`, `GLOWSTONE_DUST`)
  - **base** (string): ID базового зелья (может быть ванильным или кастомным)
  - **result** (string): ID получаемого зелья
- **effects** (array): Массив эффектов зелья
  - **type** (string): Тип эффекта (например, `FAST_DIGGING`, `JUMP`, `SPEED`)
  - **duration** (number): Длительность в тиках (20 тиков = 1 секунда)
  - **amplifier** (number): Уровень эффекта (0 = уровень I, 1 = уровень II и т.д.)

#### Примеры ванильных базовых зелий

- `POTION-AWKWARD-STANDARD` - Неуклюжее зелье
- `POTION-MUNDANE-STANDARD` - Заурядное зелье
- `POTION-THICK-STANDARD` - Густое зелье
- `SPLASH_POTION-AWKWARD-STANDARD` - Взрывное неуклюжее зелье
- `LINGERING_POTION-AWKWARD-STANDARD` - Туманное неуклюжее зелье

## 📖 Использование

### Создание нового зелья через GUI

1. Выполните команду `/cp modify`
2. В главном меню выберите "Create New Potion"
3. Следуйте инструкциям в интерфейсе:
   - Выберите тип зелья (обычное, взрывное, туманное)
   - Настройте цвет (RGB слайдеры)
   - Добавьте эффекты (тип, длительность, уровень)
   - Создайте рецепты варки (ингредиент + база)
   - Введите название зелья
4. Подтвердите создание
5. Зелье будет автоматически сохранено в `potions.json`

### Редактирование существующего зелья

1. Выполните команду `/cp modify`
2. Выберите зелье из списка
3. Внесите необходимые изменения
4. Сохраните изменения (левый клик на кнопку "Exit") или отмените (правый клик)

### Создание зелья через JSON

1. Откройте файл `plugins/CustomPotions/potions.json`
2. Добавьте новый объект в массив (следуя структуре из раздела [Конфигурация](#potionsjson))
3. Сохраните файл
4. Выполните `/cp reload` для применения изменений

**Пример**:
```json
{
  "potionId": "my-custom-potion",
  "colour": {
    "r": 100,
    "g": 200,
    "b": 255
  },
  "name": "§bМоё кастомное зелье",
  "type": "POTION",
  "recipes": [
    {
      "ingredient": "EMERALD",
      "base": "POTION-AWKWARD-STANDARD",
      "result": "my-custom-potion"
    }
  ],
  "effects": [
    {
      "type": "LUCK",
      "duration": 6000,
      "amplifier": 2
    }
  ]
}
```

### Варка зелья в игре

1. Поместите базовое зелье в стойку для варки (в любой из трёх слотов)
2. Добавьте соответствующий ингредиент в слот ингредиента
3. Если необходимо, добавьте порох дракона в слот топлива
4. Дождитесь завершения варки
5. Заберите готовое зелье

### Выдача зелья игроку

1. Выполните команду `/cp give`
2. Выберите зелье из списка
3. Зелье будет добавлено в ваш инвентарь

### Основные классы

#### Main.java
Главный класс плагина. Отвечает за:
- Инициализацию плагина
- Регистрацию слушателей событий
- Регистрацию команд
- Управление жизненным циклом плагина
- Логирование

#### Potion.java
Класс, представляющий кастомное зелье. Содержит:
- ID зелья
- Цвет (RGB)
- Название
- Тип (POTION, SPLASH_POTION, LINGERING_POTION)
- Список эффектов
- Список рецептов

#### PotionRecipe.java
Класс рецепта варки. Содержит:
- Ингредиент (Material)
- Базовое зелье (ID)
- Результат (ID)

#### State.java
Базовый класс для состояний GUI. Реализует паттерн State Machine для навигации по интерфейсам.

#### Actions.java
Система действий для обработки взаимодействий пользователя с GUI.

#### FileData.java
Управление чтением и записью данных из/в `potions.json`.

#### BrewingStandListener.java
Обработчик событий стойки для варки. Отслеживает:
- Размещение ингредиентов
- Проверку рецептов
- Запуск процесса варки
- Обновление результатов

#### LivePotionRecipe.java
Активный рецепт варки, который отслеживает процесс варки в реальном времени через `BrewClock` (внутренний класс на основе `BukkitRunnable`).

## 🔧 Технические детали

### Архитектура

Плагин использует несколько ключевых паттернов проектирования:

#### 1. State Machine (Машина состояний)
Система GUI построена на паттерне State Machine. Каждое меню представлено классом состояния (`State`), который знает, как переходить к следующему состоянию на основе действий пользователя.

**Преимущества**:
- Чёткая структура навигации
- Легко добавлять новые меню
- Удобное тестирование отдельных состояний

#### 2. Action Pattern (Паттерн действий)
Действия пользователя инкапсулируются в объекты `Action`, которые знают, как обработать текущее состояние и вернуть новое.

**Пример**:
```java
public static class ModifyPotionAction extends Action {
    @Override
    public State execute(State state) {
        // Обработка выбора зелья для редактирования
        return new PotionTypeMenu(state);
    }
}
```

#### 3. Serialization (Сериализация)
Состояния сериализуются в Base64 строки и хранятся в `localizedName` предметов GUI. Это позволяет передавать состояние между кликом пользователя и обработкой события.

**Процесс**:
1. Пользователь кликает на предмет в GUI
2. Состояние извлекается из `localizedName`
3. Действие выполняется на основе состояния
4. Новое состояние сериализуется и прикрепляется к новым предметам

### Система варки

Варка зелий реализована через `BrewingStandListener` и `LivePotionRecipe`:

1. **Обнаружение рецепта**: При размещении ингредиента проверяются все возможные рецепты
2. **Создание активного рецепта**: Если рецепт найден, создаётся `LivePotionRecipe`
3. **Запуск таймера**: Внутренний класс `BrewClock` запускается как `BukkitRunnable`
4. **Обновление**: Каждый тик обновляется прогресс варки и уровень топлива
5. **Завершение**: После завершения варки все слоты обновляются результатами

### Управление данными

#### Хранение
- Данные хранятся в JSON формате в файле `potions.json`
- Используется библиотека Gson для сериализации/десериализации

#### Загрузка
- При запуске плагина загружаются все зелья из `potions.json`
- Выполняется валидация каждого зелья:
  - Проверка уникальности ID
  - Проверка отсутствия конфликтов с ванильными зельями
  - Проверка корректности типов
  - Проверка существования базовых зелий в рецептах
  - Проверка предотвращения комбинации GLOWSTONE_DUST и REDSTONE

#### Сохранение
- При сохранении через GUI зелье сразу записывается в файл
- Автоматическое перезаполнение кэша после записи

### Обработка ошибок

Плагин включает комплексную обработку ошибок:

- **Валидация при загрузке**: Невалидные зелья пропускаются с предупреждением
- **Логирование**: Все ошибки логируются с различными уровнями (INFO, WARNING, SEVERE)
- **Режим отладки**: Включение отладки через `config.yml` для подробного логирования

### Производительность

#### Оптимизации
- Кэширование списка зелий в памяти
- Преобразование рецептов в `LivePotionRecipe` только при необходимости
- Минимизация операций с файловой системой

#### Масштабируемость
- Поддержка пагинации в GUI для больших списков зелий
- Эффективная проверка рецептов через перебор только релевантных

1. Создайте новый класс, наследующий `State`:
```java
public class NewMenu extends State {
    public NewMenu(State previousState) {
        super(previousState, new ChestInventory("Title"), new Input());
    }
    
    @Override
    public List<ItemStack> calculateInventoryItems() {
        // Реализация элементов меню
    }
}
```

2. Добавьте действие для перехода к новому меню в `Actions.java`
3. Обновите логику навигации в существующих меню

#### Добавление нового эффекта

Эффекты добавляются через стандартные типы `PotionEffectType` из Bukkit API. Поддерживаются все эффекты Minecraft.

### Отладка

#### Включение режима отладки

В `config.yml`:
```yaml
debug:
  enabled: true
  log-brewing-actions: true
  log-inventory-actions: true
```

#### Использование команды debug

```
/cp debug
```

Выводит подробную информацию о всех зельях в консоль сервера.

### Тестирование

#### Ручное тестирование
1. Запустите сервер с плагином
2. Создайте тестовое зелье через `/cp modify`
3. Попробуйте сварить его в стойке для варки
4. Проверьте выдачу через `/cp give`
5. Проверьте перезагрузку через `/cp reload`

#### Рекомендуемые тестовые сценарии
- Создание зелья с несколькими эффектами
- Создание цепочки рецептов (базовое → улучшенное → расширенное)
- Проверка валидации (невалидный ID, конфликтующий рецепт)
- Проверка всех типов зелий (обычное, взрывное, туманное)
- Проверка всех ванильных базовых зелий
